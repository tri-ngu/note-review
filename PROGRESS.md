### Game Room backend (`game-room-build` branch, `backend/`, FastAPI + Pydantic)

Built in a separate local clone (nested at `game-room-build/`, own `.git`, isolated from this docs working directory) per Tri's request, so implementation edits never touch `CONTEXT.md`/`DESIGN.md`/`PROGRESS.md`/`requirements.md` directly. Covers Todo parts 1-5 below (data model + store, HTTP endpoints, WS protocol, state machine + game logic, hardcoded fixture) — no v1 upload/Analyzer/Generator/Verifier pipeline involved, per Tri's direction to use handwritten questions for this build. Frontend (parts 6-8) not started.

- `app/models.py` — `Question`/`QuestionSet`/`PlayerState`/`Answer`/`RoomState` (Pydantic, validated fixed sizes, matches `DESIGN.md`'s Room data model).
- `app/fixture.py` — `WATER_CYCLE_QUESTION_SET`, 8 hand-written questions (new content, not the Build 1 flashcard fixture) mixing Multiple-Choice/Select-All, Claude-drafted and Tri-reviewed.
- `app/game_logic.py` — scoring brackets, correctness check (all-or-nothing for Select-All), standard/skip ranking, per-Room shuffle.
- `app/store.py` — PIN-keyed in-memory `RoomStore`, `asyncio.Lock`-guarded, PIN collision retry, TTL sweep (terminal Rooms and abandoned Lobbies alike).
- `app/session.py` — minimal HTTP-only session cookie for Host identity, set on first `POST /rooms` instead of first `/upload` (agreed with Tri, since v1's `/upload` isn't built in this session).
- `app/rooms_http.py` — `POST /rooms`, `POST /rooms/{pin}/join` (nickname auto-suffix, capacity/already-started checks), `GET /rooms/{pin}`.
- `app/rooms_ws.py` — `WS /ws/room/{pin}`, full message protocol, LOBBY→QUESTION_ACTIVE→ANSWER_REVEAL→LEADERBOARD→FINISHED state machine, server-authoritative 30s timer, Host-disconnect short-circuit.
- `app/main.py` — app wiring + periodic TTL cleanup sweep on app lifespan.

Built test-first (76 tests, `pytest`), covering the happy path plus adversarial cases: wrong-role/unknown/malformed WS messages, one-shot answer lock, wrong-round rejection, Select-All exact-match scoring through a real WS flow, mid-game disconnect semantics, a full 8-round game to natural `FINISHED`, 3-player tie ranking, and `RoomStore` concurrency (parallel `create_room`/`mutate`). Two real bugs found and fixed: a `store.mutate()` re-entry in the leaderboard→finish path that would've deadlocked `asyncio.Lock`, and a missing model-level check that Multiple-Choice questions have exactly 1 correct answer (per `CONTEXT.md`'s definition — `DESIGN.md`'s model snippet didn't enforce it). Manually smoke-tested live over `uvicorn` (create room → join → status → health). Pushed to `origin/game-room-build`.
